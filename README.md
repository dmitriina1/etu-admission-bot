# Telegram-бот для конкурсных списков ЛЭТИ

Бот проверяет поле «Список обновлен», присылает новые места и баллы владельцу и запускает прогноз Монте-Карло по команде `/forecast`.

## Команды

- `/status` — показать текущие места и баллы;
- `/check` — принудительно проверить и прислать состояние;
- `/forecast` — 300 000 симуляций для списка 2;
- `/forecast 2.2`, `/forecast 2.3` и т. д. — прогноз по коду направления;
- `/help` — справка.

## 1. Создание Telegram-бота

1. Откройте `@BotFather`.
2. Выполните `/newbot` и получите токен.
3. Напишите созданному боту `/start`.
4. Узнайте свой числовой Telegram ID через `@userinfobot`. В личном чате он является `OWNER_CHAT_ID`.

Никому не публикуйте `BOT_TOKEN`, `WEBHOOK_SECRET` и `CRON_SECRET`.

## 2. Локальный запуск

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

$env:BOT_TOKEN="токен"
$env:OWNER_CHAT_ID="ваш_id"
$env:WEBHOOK_SECRET="случайная_длинная_строка"
$env:CRON_SECRET="другая_случайная_строка"
uvicorn bot:app --reload
```

Локально webhook требует публичный HTTPS-адрес, поэтому проще сначала развернуть проект.

## 3. Бесплатная публикация на Render

1. Создайте новый репозиторий GitHub и загрузите туда файлы этой папки.
2. На Render выберите **New → Blueprint** и подключите репозиторий. Render прочитает `render.yaml`.
3. Введите секреты `BOT_TOKEN` и `OWNER_CHAT_ID`. Значения `WEBHOOK_SECRET` и `CRON_SECRET` Render создаст автоматически.
4. После деплоя откройте **Environment** и скопируйте созданные `WEBHOOK_SECRET` и `CRON_SECRET`.
5. На своём ПК в папке проекта выполните:

```powershell
$env:BOT_TOKEN="токен_от_BotFather"
$env:WEBHOOK_SECRET="значение_из_Render"
python set_webhook.py https://ИМЯ-СЕРВИСА.onrender.com
```

## 4. Автоматическая проверка обновлений

На cron-job.org создайте задачу:

- URL: `https://ИМЯ-СЕРВИСА.onrender.com/cron/check`
- интервал: каждые 5 минут;
- HTTP method: `GET`;
- header: `X-Cron-Secret: значение_CRON_SECRET_из_Render`.

Cron одновременно проверяет сайт и не даёт бесплатному сервису уснуть. При первом запуске бот только запоминает текущее время обновления. После следующего изменения пришлёт сообщение автоматически.

## Проверка

1. Напишите боту `/status`.
2. Напишите `/forecast 2.3`.
3. Откройте вручную `/cron/check` через cron-job.org с правильным заголовком — ответ должен быть `initialized` или `unchanged`.

## Настройки

Переменные окружения:

- `APPLICANT_CODE=1203485`;
- `FORECAST_SIMULATIONS=300000` — количество симуляций **на каждый сценарий**;
- `FORECAST_LIST=2` — список для команды `/forecast` без аргумента;
- `SEED=20260723` — повторяемость прогноза.

## Замечания

- Время обновления ищется регулярным выражением. Если ЛЭТИ изменит текст или разметку, бот сообщит ошибку.
- Бесплатный Render использует временную файловую систему, поэтому состояние хранится в памяти. Cron каждые 5 минут обычно сохраняет процесс активным. После рестарта первое сравнение заново инициализируется без ложного уведомления.
- Прогноз остаётся сценарной оценкой, а не официальной гарантией поступления.

## Обновление: 13 направлений и /realplace

Команда `/status` ищет код во всех 13 бюджетных списках и показывает только найденные направления. Режим «Только с согласием» удалён.

- `/directions` — список кодов направлений.
- `/forecast 2.3` — прогноз для направления 2.3.
- `/realplace` — расчёт распределения по приоритетам и бюджетным местам во всех списках.

Существующая таблица `bot_users` не меняется, поэтому сохранённые коды пользователей остаются на месте.


## Таблица рейтинга

Команда `/table 2.3` выводит кандидатов выбранного направления от первого места до строки пользователя включительно: место, код поступающего, общий балл и его состав.

## Порядок при одинаковом общем балле

Во всех командах (`/status`, `/table`, `/forecast`, `/realplace`) известные результаты сортируются одинаково:

1. общий конкурсный балл;
2. специальная дисциплина;
3. иностранный язык;
4. индивидуальные достижения;
5. ID поступающего как последний критерий.


### Как прогноз обрабатывает нулевые компоненты

- `Ин. яз = 0` — кандидат считается выбывшим и в прогноз не включается.
- `Спец. дисциплина = 0`, но иностранный язык есть — балл по дисциплине моделируется отдельно.
- `ИД = 0`, но экзамены есть — возможные ИД моделируются отдельно.
- Уже известные ненулевые компоненты не изменяются.
- При равном общем балле применяются критерии: спецдисциплина, иностранный язык, ИД, код поступающего.
